# RISC-V 板部署说明

## 已知环境

- 目标板 IP：`192.168.31.105`
- 已占用端口：`8000`、`8080`
- 本项目默认端口：`3001`
- 运行模式：局域网本地服务，不发布到公网

## 环境要求

- 64 位 Linux RISC-V 系统
- Node.js `22.13.0` 或更高版本
- `pnpm` 9 或 10
- 至少 1 GB 可用内存；若构建内存不足，建议在电脑构建后把 `dist/` 一并传到板上

## 自动部署步骤

1. 解压交付包并进入 `mario-pixel-quest`。
2. 检查 `3001` 是否空闲：`ss -ltn | grep ':3001 ' || true`。
3. 如果 `3001` 被占用，选择一个不等于 `8000`、`8080` 的空闲端口，并在启动命令中替换端口。
4. 安装、构建并运行回归测试：

   ```bash
   corepack enable
   pnpm install --frozen-lockfile
   pnpm test
   ```

5. 启动：

   ```bash
   pnpm start:riscv
   ```

6. 从同一局域网打开 `http://192.168.31.105:3001/`。

也可以直接运行自动脚本；它会从 `3001` 开始寻找空闲端口，并始终跳过 `8000`、`8080`：

```bash
./scripts/deploy-riscv.sh
```

## 自定义端口启动

例如改用 `3002`：

```bash
pnpm exec vinext start -H 0.0.0.0 -p 3002
```

不要使用 `8000` 或 `8080`。

## 后台运行示例

如果系统已有 `systemd`，建议让部署代理创建服务并设置工作目录、普通用户、自动重启。启动命令应为：

```bash
pnpm start:riscv
```

部署代理应在启动后验证 `curl -I http://127.0.0.1:3001/` 返回成功状态，并打印局域网访问地址。

## RISC-V 依赖兼容处理

如果某个前端构建依赖没有提供 RISC-V 预编译包，不要删除源码。可在另一台 Node.js 22 电脑上执行 `pnpm install && pnpm build`，再将项目中的 `dist/`、`package.json`、锁文件和运行依赖传到板上；或者由 OpenClaw/DeepSeek 将项目迁移成等价的纯静态 Vite 构建。迁移时必须保留四个关卡、1–2 的完整四段路线与敌人/金币配置、四座升降台、跨关卡人物保持、操作方式、人物精灵和游戏数值，并重新运行 `tests/` 中的回归测试。
