Super Wangjian 是怎么问出来的

这一页是第 6 组做《Super Wangjian · Pixel Quest》时真正用过的提示词，原样收录，没有删改。游戏本身有一千多行代码 —— 但同学写的不是代码，是下面这几段话。

🎮一段话换来四个关卡 🖼️一段话处理人物精灵 📦一段话把它部署上板子
怎么看这一页

三段提示词，三件不同的事

留意它们的共同点：说清楚要什么、说死不能变的地方、说清楚怎么算做完了。这三件事写得越具体，智能体返工越少。

1 产品实现提示词 —— 让它把游戏做出来 ONE SHOT

整个游戏本体来自这一段。注意里面全是可以被验收的具体数字：几只栗宝宝、几枚金币、哪一关没有食人花。

在新文件夹中制作一个高精度的马里奥小游戏，不发布网站。标题使用 SUPER WANGJIAN。补全 World 1–1 至 1–4，按原版地图网格复刻，修正 1–1 金币位置。World 1–2 按原版 192×15 图块地图和数据重建地表入口、地下主路线、27 金币隐藏房、14 只栗宝宝、3 只绿乌龟、1 只红乌龟，删除该关全部食人花，保留四座成对反向移动升降台、正常出口地表和屋顶 Warp Zone。1–1 至 1–3 需要旗杆下滑、终点旗下降、人物自动走进城堡、城堡旗升起的完整过关动画。提高人物跳跃高度。把用户提供的像素人物“王健”做进游戏，开局提供“经典马里奥 / 王健”人物选择，切换关卡时必须保持所选人物。为两名角色分别适配蘑菇保护框。键盘、鼠标和触控都可操作。保留计分、金币、生命、暂停、声音开关和连续过关流程。地图数据与测试共用同一来源，并真实走通入口、隐藏房往返、正常出口和旗杆路线。
💡最后一句是关键：「地图数据与测试共用同一来源」 —— 这一句直接决定了地图不会和验收规则对不上。提要求的时候顺手把「怎么防止出错」也说了。
2 人物资源处理提示词 —— 把人物抠成透明图 图像编辑工具

这一段是给内置图像编辑工具的，用来生成游戏里那张透明的人物精灵图。英文写的，因为图像模型对英文指令更稳。

Use case: background-extraction Asset type: four-frame pixel-art character sprite sheet for a browser platform game Primary request: preserve the four existing character poses exactly and isolate them on a perfectly flat solid #ff00ff chroma-key background suitable for transparent removal. Input image: the supplied image is the edit target and identity/pose/color reference. Composition: keep the same left-to-right order: standing, running, jumping, celebrating; keep generous separation and do not crop any pose. Style: exact crisp pixel art, no antialiasing, no reinterpretation. Constraints: keep the character's face, glasses, black suit, white shirt, striped blue tie, proportions, poses, lighting, pixel edges, and all details unchanged. Background must be one uniform #ff00ff with no gradient, texture, shadow, text, watermark, or extra object. Do not use #ff00ff inside the character. Avoid: redesign, extra frames, missing limbs, blurred edges, altered identity, changed pose, changed clothing.

生成的洋红底图再用本地色键处理抠掉背景，最终得到 character-sprites.png。

💡为什么选 #ff00ff 这个粉紫色当背景？因为人物身上不会出现这个颜色 —— 这样抠图时就不会把衣服一起抠掉。Avoid 那一行同样重要：先把不想要的结果说出来。
3 部署提示词 —— 交给板子上的智能体 OpenClaw / DeepSeek

这一段是写给跑在 RISC-V 板子上的智能体的，让它自己把项目装好、跑起来、验证通过。

请解压随消息提供的 mario-world1-riscv-openclaw-bundle.tar.gz，部署其中的 mario-pixel-quest 项目。 目标机器是一块 RISC-V Linux 板，局域网 IP 为 192.168.31.105。端口 8000 和 8080 已被其他服务占用，严禁停止、覆盖或修改这两个服务。优先使用端口 3001；启动前先用 ss -ltn 检查，若 3001 也被占用，则自动选择 3002、3003 等空闲端口，并在完成信息中明确告诉我最终地址。

后面跟着 8 条硬性要求，摘几条关键的：

  1. 先读 README.md、RISCV_DEPLOY.md、package.json 和源码，再动手。
  2. 列出全部必须保留的功能（四个关卡、人物选择、1–2 的四条路线、过关动画……），一样都不能少。
  3. 服务绑定 0.0.0.0 以便局域网访问；不发布到公网，不配置外部云服务。
  4. 不许碰 8000、8080 上的任何进程，不许执行破坏性系统命令。
  5. 万一依赖没有 RISC-V 版本，保持玩法和视觉不变，把项目转成纯静态版本，且不得替换人物图。
  6. 先跑 pnpm test 再启动；用 curl 验证首页能打开、HTML 里有「选择人物」「经典马里奥」「王健」。不许删测试。
  7. 最后只报告：关键步骤、最终端口、访问 URL、守护方式、是否通过验证。
🛡️这段里真正值钱的是那些「不许做什么」：不许动别人的端口、不许删测试、不许换人物图、不许发到公网。给智能体开权限之前，先把红线画出来 —— 这是让它替你干活时最该学会的一件事。
